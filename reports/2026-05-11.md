## 2. 막힌 지점 — 정확한 진단

```
[aic_model] Loading policy module: aic_example_policies.ros.CheatCode  ← OK
[aic_model] Using policy: CheatCode                                    ← OK
[aic_model] on_configure(LifecycleState(label='unconfigured', ...))    ← OK
[aic_model] Policy.__init__()                                          ← OK
[ERROR] aic_model lifecycle is not in the active state                 ← 여기서 막힘
[WARN] No transition matching 4 found for current state unconfigured
[ERROR] Unable to start transition 4 from current state (1, 'unconfigured')
[WARN] No transition matching 2 found for current state unconfigured
```

**원인 추정**:
1. 호스트 pixi env가 docker eval 컨테이너의 zenoh router에 lifecycle service를 등록 못 함
2. `AIC_MODEL_PASSWD`/`AIC_EVAL_PASSWD` ACL 매칭 또는 RMW zenoh 구성 차이
3. 토킷이 docker compose로 두 컨테이너를 같은 환경(같은 image, 같은 host network)에서 띄울 때만 정확히 동작하는 패턴일 가능성

**해결 방향 (다음 세션에서)**:
- **model도 docker로 띄움** — 같은 `aic_eval` image, 같은 host network. 토킷 의도한 환경과 일치.
```bash
docker run --rm --name aic_model --gpus all --network host \
  -e AIC_EVAL_PASSWD=devpw -e AIC_MODEL_PASSWD=devpw \
  -e AIC_ROUTER_ADDR=localhost:7447 \
  -e RMW_IMPLEMENTATION=rmw_zenoh_cpp \
  -e ZENOH_ROUTER_CHECK_ATTEMPTS=-1 \
  --entrypoint "" \
  ghcr.io/intrinsic-dev/aic/aic_eval:latest \
  bash -lc 'source /ws_aic/install/setup.bash && \
            ros2 run aic_model aic_model --ros-args \
              -p use_sim_time:=true \
              -p policy:=aic_example_policies.ros.CheatCode'
```
